# Borrow review tools' shared selection, fast focus, and explicit decision scope

Read 12 November 2026. The strongest starting points are Figma/Miro for seeing relationships, Lightroom for switching views, Chromatic/Percy/Applitools for changed-only review, Frame.io for time, and specialist queues for finishing a bounded set. No single surface serves every kind of evidence equally well.
This is a documentation-based comparison, not a hands-on usability ranking. “Strongest” means a particularly useful combination of context, precise feedback, low navigation effort, and clear progress. **Cost** below estimates actions after opening the work; it excludes login, loading, author preparation, and the time needed to judge the evidence. **Breaks** mixes documented limits with explicitly reasoned failure cases; no click timings or pass-reduction claims were measured.
Public product material alone went to external services. Local context came from the common brief and the existing D2, kinds-of-work, baseline, and capabilities reports; no private messages or project content were uploaded. `DATA` below means `/Users/changlee/projects/agent-annotate/shared/agents/from-zero-20261112`.

## 2. Moving between together and one at a time

- **Board → focus:** Miro's canvas/slide controls and Figma's linked inline preview change the view of the existing object. Cost: one mode action, not finding/exporting/reopening the item. Keep the selected item visible on return; a giant zoomed-out board otherwise loses the reviewer.
- **Queue with a filmstrip:** Lightroom preserves the selected collection beside Loupe/Compare/Survey; Playwright's screenshot strip locates a moment in a run. Cost: arrow/hover/click, no page change. Filmstrips fail when images are indistinguishable; names, status, and a current-item indicator must supplement them.
- **Split compare → overlay:** Figma, Chromatic, Frame.io and Filestage show broad differences side by side, then fine differences through overlay/diff controls. Cost: a view toggle; linked pan/zoom avoids duplicate movement. Keep versions labelled; allow unlinking for deliberately different regions. Frame.io's static-image overlay should not be described as a video overlay.
- **Linked panes:** Tableau selection filters detail; Playwright interval selection filters steps/logs/network; RadiAnt synchronizes related image views. Cost: one selection propagates. The switch becomes expensive or misleading if the reviewer cannot see what is linked or reset a filter.
- **Keyboard stepping:** Chromatic supports A/D then Option-arrow; Frame.io has bracket asset stepping and I/O ranges; Lightroom uses G/E/C/N for views; Word can decide-and-advance. Cost: one or two actions per item after learning keys. Keys must not trigger decisions while typing; touch controls need equivalent visible actions.
- **Batch decisions with exceptions:** Applitools/Reddit offer selected-set actions; Percy offers matching-change groups; Word distinguishes all shown from all. Cost: inspect the group, remove exceptions, apply once. Borrow the bounded selection, count and exception list; automatic acceptance outside that set is an extra behavior requiring explicit visibility.
- **Review again only where changed:** GitHub resets Viewed when a file changes; Percy carries forward identical approvals. Cost: inspect the changed subset. A wider semantic change can invalidate apparently untouched material; a changed-only view still needs access to the whole flow and its dependencies.

## 3. Feedback mechanics

- **At a place:** Figma and BugHerd pin a note to a screen/object/element. Cost: activate, point, type, send. It saves naming coordinates; it breaks when the target moves or the live page no longer has that state. Retain artifact version, screen and captured evidence alongside the anchor.
- **At a region:** Figma supports drag-to-select comment regions; Frame.io supports boxes/arrows/free drawing. Cost: one drag or drawing gesture plus the note. Good for spacing, grouping and “this whole area”; an unlabelled rectangle becomes ambiguous after reflow.
- **At a time:** Frame.io supports frame and range anchors, comment-to-playback and I/O selection; Filestage captures timestamps. Cost: pause/type for a point, two range endpoints for an interval. A time range needs version identity; edits that insert time can invalidate alignment.
- **At a step:** Figma supplies named prototype flows and restart; Playwright supplies recorded action → before/after → filtered logs. Cost: select the step rather than narrate the route. Proposed borrowing: feedback stores flow, step and entry state together; prototype or trace evidence must remain distinguishable from a freshly tried service.
- **At a number:** Tableau's mark annotations can include data values; Grafana associates notes with events/time ranges; k6 identifies the compared runs and metric. Cost: select the mark or interval, write once. Preserve metric name, unit, filters, aggregation and run/time; a live value alone is not stable evidence.
- **Mark many at once:** select a range, check named items, or select a visible filtered group; Lightroom, Reddit, Applitools and OpenRefine provide useful models. Cost: selection plus one action rather than repeating the action. Show affected count and scope; do not silently extend “all shown” to hidden pages or environments.
- **“All these, the same change”:** OpenRefine's identical-cell edit and selected cluster merges, Relativity's defined-group propagation, and Percy's matching-diff groups are concrete precedents. They apply edits/labels/acceptance, respectively—not a universal shared comment. Proposed borrowing: one instruction linked to an inspectable list of targets, with per-target exceptions and completion evidence. Similarity alone must not decide membership.
- **Collect, then send:** GitHub batches comments into one review; Filestage separates comments from the final review decision. Cost: compose notes in place, then finish once. This preserves a coherent pass; a saved draft or resolved thread must not be presented as accepted work.

## 4. Several screens and tablets

- **Lightroom Classic makes real use of a second monitor:** grid/filmstrip on the main display, large selected image on the other. Its second Loupe can follow selection, follow hover, or stay locked to a reference; Compare/Survey are available too. One view control/shortcut changes roles. Documented trap: ordinary commands still target main-window selection. [Source](https://helpx.adobe.com/lightroom-classic/help/displaying-library-second-monitor.html)
- **RadiAnt uses separate viewer windows across monitors**, with same-study series automatically synchronized and optional cross-reference lines. Duplicate-window and sync controls avoid rebuilding the comparison. It is a Windows product reference, not a proposed Mac installation. **OHIF's documentation explicitly calls its multi-monitor service basic and not a full solution** despite describing two-screen configurations; borrow its layout rules, not an unverified seamless-monitor claim. [RadiAnt](https://www.radiantviewer.com/dicom-viewer-manual/multiple-windows.html), [OHIF limitation](https://docs.ohif.org/llm/platform/services/data/MultiMonitorService.md)
- **Playwright UI Mode** can pop snapshots into separate windows for side-by-side inspection. Cost: pop out each chosen state; window placement still costs effort. **Miro** documents a separate presenter-notes window; that is an additional role, not proof of independent linked review panes across several computers. [Playwright](https://playwright.dev/docs/test-ui-mode), [Miro](https://help.miro.com/hc/en-us/articles/34307373858450-Presentation-mode)
- **LiquidText on a tablet** uses touch/ink to join excerpts and bring distant passages together. **PDF Expert** offers simultaneous PDF windows on iPad, Pencil annotation, and Mac-to-iPad Sidecar use. Cost: arrange windows/choose a pen once; point/write directly afterward. PDF comparison is not automatic synchronized review-state sharing; Sidecar has compatible-device/account requirements. [LiquidText](https://www.liquidtext.net/liquidtextadeeperdive), [PDF windows](https://support.readdle.com/pdfexpert/en_US/reading-pdfs/view-two-pdfs-side-by-side-on-ipad), [Pencil](https://support.readdle.com/pdfexpert/en_US/tips-and-tricks/work-with-apple-pencil-in-pdf-expert), [Sidecar](https://support.readdle.com/pdfexpert/en_US/tips-and-tricks/improve-your-workflow-with-sidecar-and-camera-continuity)
- **Three Macs are not three monitors on one computer.** None of these documentation reads establishes a shared active selection, pinned reference or unfinished-review position across that desk. Design direction: keep explicit screen roles and allow a pane to follow or stay pinned; laptop/tablet collapses those roles into switches over the same review set. This is a proposal, not a verified feature of the products above.

## 5. AI assistant layouts as references; remaining gaps

**Artifact beside chat:** Claude opens an artifact next to a conversation; current templates include direct editing and anchored comments. ChatGPT's official documentation describes supported file previews/annotations; its image viewer already switches Focused/Canvas views and supports comments over multiple selected images. Cost: open preview, select a target, write/send a revision; context is near the work. These are useful references, not a mandate to reproduce their layout. [Claude artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them), [Claude comments](https://support.claude.com/en/articles/17457950-use-artifacts-with-a-keyboard-or-screen-reader), [OpenAI file review](https://learn.chatgpt.com/docs/artifacts-viewer.md), [OpenAI image views](https://learn.chatgpt.com/docs/image-generation.md)

**What that default arrangement cannot supply by layout alone:** a legible many-screen desk, exact cross-version acceptance scope, a whole-flow coverage map, shared progress across heterogeneous evidence, or proof that background work continues. Chat and a preview can contain a custom tool providing these things; the mere adjacency of chat and artifact does not provide them. Current image canvases and Claude's newer design templates mean “AI assistants only show one static artifact” would be an inaccurate criticism.

No universal absence is proved by this sample. The following are opportunities suggested by the documented boundaries:

- **One review set, several faithful views:** preserve object/version, selection, exceptions and reading position across board, focus, compare, timeline and try-it. Specialist tools handle their own medium; crossing plan → flow → live behavior → performance usually changes applications and evidence identities.
- **A shared instruction with visible scope:** make one multi-target correction inspectable and report each target's result. Bulk acceptance and automatic propagation exist, but their scope differs and may reach farther than the reviewer expects.
- **Acceptance that survives only while its evidence does:** combine GitHub-style invalidation with exact version comparisons and the previous request beside its proposed fix. Resolved comments and green baselines alone do not show that the intended result was achieved.
- **A guided path with whole-work escape routes:** focus lowers load but can hide missing branches, states and environments. Let a reviewer see unreviewed coverage, compare siblings, and return to exactly where the guided pass stopped.
- **A real desk that travels:** selection-following and reference-locking are mature within Lightroom/RadiAnt; a comparable arrangement across separate Macs, then one laptop/iPad, was not established here. Preserve the review, not just window geometry.
- **Evidence of continued work:** none of the reviewed comment/canvas mechanics by itself proves a worker is progressing. Status must come from actual execution/evidence records, with blockers distinct from unfinished visual review; this is outside a preview panel's job.
