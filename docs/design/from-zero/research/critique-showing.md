**The screen I would combine.** Use Sitting's finite running order and honest unknown/remaining-time door, Letter's result enclosure and evidence structure, Thread's direct context-specific marking, and Picture's fixed association between an exception and its goal. The result, not the counterpart's explanation, takes most of the display.
1. On the desk: a narrow order at left; actual result in the centre at its native scale; a small right rail with “For your judgement: does this feel clear?” and “Proved: 5 · Unproved: 1 · Seen today 10:12.” No wall of check text. Phone: full-width result, one judgement sentence, fixed Mark/Accept-viewing controls; the proof rail opens as a bottom sheet without losing the marked location.
2. “Mark” freezes the exact revision. Tap a control/object, select words/cell, draw a region, or freeze a recording and select a time range. Keyboard can choose the same named targets. “Something is missing / wrong with the whole thing” is always available, including numeric results. Switching Interact/Mark prevents a purchase button being triggered while pointing. A mark retains build, viewport, device, account scope, step and frame; it returns to the same object after a fix, with before/after comparison.
3. Each done line opens its smallest directly useful evidence: a replay at the failing step, changed-only rows with saved readback, a role pair showing allowed/denied, or paired runs with spread. Name exact revision/target and independent checker; show failure/unknown first. Full raw evidence is one further action. No automatic long report; no requirement to inspect every green criterion.
4. Appearance and behavior have separate state. “Looks right” records human judgement; “Proved to work on this phone/build” names an observed result. Neither fills the other. A simulator, preview, sampled row set or estimated bill says exactly that. Material unproved criteria block ready; an explicitly accepted residual is visible, scoped and never silently converted to a pass.
5. A native/car result has a launch/mirror/capture handoff with a return link to this same showing, not a second tracking destination. A real phone recording, exact build/device and parked physical test can be reviewed here; an audio/GPS/car interaction still must be exercised on the intended hardware. An external account returns a redacted saved-state capture and stable row IDs. Live web uses the actual served build with two agreed viewport buttons, recording the interaction as well as the pixels.
6. Before an irreversible step, replace generic Accept with the exact act: “Send this text to these 380 people,” “Apply these 12 prices,” or “Release this build to this audience.” Show final render/amount/audience/target, affected manifest, what cannot be recovered, checked undo/restore where possible, and existing authority.
