Status: approved by Chang on 2026-11-04 (card #130) and activated the same day; see [the activation report](ci-m1max16-20261104.md). Where the activation differs from this plan, the report wins: credentials come from Infisical, and the source cache, Playwright cache and placement checks are as described there.

## Trigger and return path

Keep Windmill in Docker on the M1. Reuse the existing wm-test request/receipt protocol and fixed host executor rather than installing a Windmill worker on macOS. The dispatcher launches a deterministic Python command in an Orca terminal on environment M1Max16; it must select that environment explicitly and fail closed if remote placement is unverified. There is no agent launch.

Initial trigger: `wm-test agent-annotate full --sha <40-character-commit> --work-item agent-annotate-va0`. The existing clean-HEAD `scripts/ci.py --full` route can submit this without inspecting logs; `--local` is the explicit override. Submission and wait are scripts and use zero AI tokens. A passing job returns one result line and a Windmill evidence link, with merged JUnit and per-chunk logs retained as artifacts. Runtime port-allocation/publisher integration tests finish and clean up owned servers before browser chunks run concurrently; browser startup checks the child PID and page directory through loopback capabilities, not just any HTTP 200.

After the first remote and backup proofs, add a Windmill schedule polling trusted PR heads every minute. It submits each new SHA once after the quick check passes, sets a named `full-suite` GitHub status pending and then success/failure on that exact SHA, and cancels superseded admissions without assuming that cancellation has cleaned up a running host process. This avoids exposing the private Windmill endpoint to GitHub-hosted runners. A fine-grained GitHub credential needs repository read and commit-status write only. PR forks/untrusted branches require human authorization before execution under the host user. The one-command trigger remains available and uses the same deduplication key.

## Placement, backup and cleanup

M1Max16 is the primary; this M1 is the automatic backup. One heavy slot per machine, isolated clean checkout/venv/state/tmp per run, browser port leases in 18700–18799, explicit source/profile/toolchain/environment hashes, bounded timeouts and process-group cleanup. Both targets run the same candidate SHA and frozen uv.lock. No installed annotate package, live page, live route, M5 or shared development checkout is changed.

Fail over automatically on primary preflight unavailability before execution, or after positive proof that a started attempt has exited and cleanup succeeded. An assertion failure is a test failure, not a reason to seek a green backup. A lost connection or uncertain ownership yields HOLD and a failed/blocked status; do not launch overlapping work on the backup. If both targets are unavailable, return infrastructure failure with the Windmill link. Windmill remains on the M1, so controller availability still depends on the M1; runner backup is not controller failover. Preserve attempt/host identity in the receipt, and do not hide a primary infrastructure failure in the backup result.

## Installation and authorization gate

Known from the dispatch: M1Max16 has uv, Python 3.12, annotate 2.28.2 and Command Line Tools. This worker has not independently inspected or changed it. Chrome plus the Playwright browser downloads are already approved. Additional approval requested: Node LTS (needed by `node --check`), the repo-local frozen dev/mcp/browser Python environment, and a reviewed copy of the fixed host executor plus private config/credential files and scratch/artifact directories. No Windmill worker or host daemon is proposed. Use the existing Orca remote bridge after verifying its exact environment/terminal placement capabilities; if it cannot launch a plain command there, return for a placement decision instead of silently installing another service.

The repository is public (verified through GitHub). Provision a dedicated allowlisted Git source cache on each execution host, fetch the requested full SHA over unauthenticated HTTPS, and verify the exact commit and archive/profile hashes before creating the job checkout; no GitHub credential belongs in a test child. The cache is repository data, not a shared working checkout.

The existing executor replaces HOME and XDG_CACHE_HOME with job-local directories. Installing WebKit in the login user's default cache alone is insufficient: explicitly configure PLAYWRIGHT_BROWSERS_PATH to a dedicated versioned browser cache on each host, verify that the locked Playwright version can launch it under the sanitized job environment, and keep writable application state in job scratch. Chrome uses its approved absolute application path. These browser-path and source-cache settings are part of the reviewed executor/private-config activation gate.

M1 already has Chrome, Playwright browser cache, uv and the pilot host executor; this work adds only its checkout-local .venv. Its local wm-test config says ready=true but records submitter/publisher credential expiry on 2026-10-27. Activation must renew narrowly scoped identities, refresh pinned executor/profile/toolchain hashes and validate actual auth; the ready flag alone is insufficient.

Changes needing approval in Windmill: dispatcher target selection and backup policy; receipt schema/validation including host identity; scoped credential renewal; polling schedule and GitHub status reporter. Keep existing pilot recovery/cancel/receipt semantics. Propagate the native runner summary (chunk counts, duration and failed IDs) through the wm-test client and Windmill result; retain the full profile's required chunk logs and merged JUnit, and validate their hashes before reporting success. First prove remote pass and a same-SHA comparison against the M1 local/profile baseline, a forced primary-preflight failure with backup pass, assertion failure without fallback, disconnected/unknown execution without duplicate fallback, cleanup, and exact-SHA status reporting. Audit cancellation/timeout cleanup independently of pytest finalizers: test publishers use start_new_session, so escaped server/browser processes must be reconciled by exact identity and unique job paths before declaring cleanup complete. A process group alone is insufficient proof for detached publishers.

## Judgment and tokens

Dependency setup, source verification, lint, syntax checks, test selection, execution, JUnit parsing, skip allowlist checking, cleanup, fallback, artifact validation and status publication are deterministic scripts. Passing runs require **0 agent launches and 0 AI tokens**. Existing GitHub checks and the pilot executor already consume zero AI tokens; agent-driven local runs add unmeasured model tokens for starting, monitoring and interpreting them, so a numeric historical baseline is not claimed.

A failing assertion, changed product expectation, security judgment or flaky-test fix may require a developer. Windmill first returns the failing IDs and logs without invoking a model. The coordinator explicitly deferred optional Haiku triage. No model integration is part of activation; a failed run returns evidence to a developer. No small-model call is necessary for a passing run or infrastructure fallback.

## Dependency boundary

Direct inspection confirms that the argv/deployment/version-guard fixes already exist in the base branch; no additional runtime cherry-pick is needed. The pilot verified-install helper remains absent and is unnecessary because release installation is outside this task. No release-wheel install or post-test deployment belongs to this automation.
